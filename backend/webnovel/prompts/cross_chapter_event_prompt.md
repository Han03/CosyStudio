system_prompt: 你是一位专业的跨章节事件分析师，擅长识别开放悬念与倒计时事件的埋设和回收，输出严格JSON
user_prompt: |
  请对本章内容做跨章节事件分析：识别【本章新出现的开放悬念与倒计时事件】与
  【活跃清单中被回收/触发的开放悬念与倒计时事件】。

  【本章内容】
  {chapter_content}

  【活跃开放悬念】
  {active_loops}

  【活跃倒计时事件】
  {active_countdowns}

  判断规则：
  1. 新开放悬念：本章正文中**新出现**、尚未解决的线索（物品/设定/事件/人物疑点等），且不在活跃开放悬念清单中；
     前面章节已交代过的物品、设定或事件，以及已在清单中的悬念，不得作为新悬念提取。
  2. 新倒计时事件：本章**新出现**的倒计时/期限（"还剩X天""X日后""限期…"），且不在活跃倒计时清单中。
  3. 回收判断：清单中某悬念在本章被明确解决、揭示、兑现时，输出其编号（对应【活跃开放悬念】中的序号）；
     仅被提及、被推进但未解决的不算回收。
  4. 触发判断：清单中某倒计时在本章到期、被兑现、被取消时，输出其编号（对应【活跃倒计时事件】中的序号）。
  5. 同一事件不得既算新增又算回收/触发：清单中的事件若在本章被解决，只计入回收/触发；新出现的未解决线索，只计入新增。

  输出JSON格式（只输出JSON）：
  {{
    "new_open_loops": [
      {{"content": "悬念内容描述", "tier": "核心/支线/装饰", "target_chapter": 0, "evidence": "原文证据片段"}}
    ],
    "new_countdowns": [
      {{"event_name": "倒计时事件名", "start_countdown": "倒计时描述（如：还剩15天）", "evidence": "原文证据片段"}}
    ],
    "resolved_open_loop_indices": [0, 2, 5],
    "resolved_countdown_indices": [1, 3]
  }}
  - tier：核心伏笔回收周期50-300章，支线30-100章，装饰10-30章；target_chapter：预计回收章节（0表示未定）
  - new_open_loops / new_countdowns 无内容时输出空数组；resolved_open_loop_indices / resolved_countdown_indices 无回收时输出空数组。
